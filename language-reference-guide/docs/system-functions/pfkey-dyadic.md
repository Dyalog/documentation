# <span>Set Programmable Function Key</span> `R←X ⎕PFKEY Y`{{key}}

This function sets the definition of a [programmable function key](#programmable-function-keys). [Monadic `⎕PFKEY`](pfkey-monadic.md) returns it without changing it.

!!! Info "Information"
    When Dyalog runs through [Ride](https://dyalog.github.io/ride), `⎕PFKEY` sets and returns definitions, but pressing a function key does not type them. Ride defines function keys in the **Shortcuts** tab of its **Preferences** dialog box instead.

<h2 class="example">Examples</h2>

Keys 1 and 2 enter system commands, and key 3 presses keys 1 and 2:

```apl
      (')FNS',⊂'ER')⎕PFKEY 1
┌─┬─┬─┬─┬──┐
│)│F│N│S│ER│
└─┴─┴─┴─┴──┘
      (')VARS',⊂'ER')⎕PFKEY 2
┌─┬─┬─┬─┬─┬──┐
│)│V│A│R│S│ER│
└─┴─┴─┴─┴─┴──┘
      'F1' 'F2'⎕PFKEY 3
┌──┬──┐
│F1│F2│
└──┴──┘
```

Key 12 moves the text to the right of the cursor to the start of the line. It selects the text (`Rl`), cuts it (`CT`), moves the cursor (`LL`), and pastes the text (`PT`):

```apl
      'Rl' 'CT' 'LL' 'PT'⎕PFKEY 12
┌──┬──┬──┬──┐
│Rl│CT│LL│PT│
└──┴──┴──┴──┘
```

## Left Argument

`X` is a character scalar or vector, the new definition of the key. Each item is either a character, which is typed as it is, or an enclosed [keycode](#programmable-function-keys), which is pressed. `''` removes the definition.

An unknown keycode signals `KEY CODE UNRECOGNISED`. An item that is a matrix or a higher-rank array signals `KEY CODE RANK ERROR`, and a numeric or nested item signals `KEY CODE TYPE ERROR`. A definition that does not fit in the [buffer](#programmable-function-keys) signals `LIMIT ERROR`, and the key keeps its previous definition.

## Right Argument

`Y` is a simple integer scalar from `0` to `255`, the number of a [programmable function key](#programmable-function-keys).

## Result

`R` is `X`.

## Programmable Function Keys

A programmable function key has a number `n` from `0` to `255`, and is pressed by any keystroke that generates the keycode `Fn`. Pressing it has the same effect as typing the keystrokes in its definition one after another, in the Session window, Edit Windows, and Trace Windows. [`⎕SR`](sr.md) ignores the definitions.

Under Microsoft Windows, the keycodes `F1` to `F48` are generated by the function keys <kbd>F1</kbd> to <kbd>F12</kbd>, on their own and with modifier keys:

|Keycodes|Keystrokes|
|--------|----------|
|`F1` to `F12`|<kbd>F1</kbd> to <kbd>F12</kbd>|
|`F13` to `F24`|<kbd>Shift</kbd>+<kbd>F1</kbd> to <kbd>Shift</kbd>+<kbd>F12</kbd>|
|`F25` to `F36`|<kbd>Ctrl</kbd>+<kbd>F1</kbd> to <kbd>Ctrl</kbd>+<kbd>F12</kbd>|
|`F37` to `F48`|<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>F1</kbd> to <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>F12</kbd>|

These are the defaults, which the [**Keyboard Shortcuts** tab](../../windows-installation-and-configuration-guide/configuring-the-ide/configuration-dialog.md#keyboard-shortcuts-tab) of the **Configuration** dialog box can change. [`⎕KL`](kl.md) gives the keystroke that generates a keycode, and `⎕KL'F',∘⍕¨⍳48` gives them all:

```apl
      ⎕KL'F1' 'F13' 'F25' 'F37'
 F1  Shift+F1  Control+F1  Control+Shift+F1
```

In a terminal under Unix, the input translate table maps keystrokes onto keycodes. By default, the function keys <kbd>F1</kbd> to <kbd>F10</kbd> generate `F1` to `F10`.

A definition is a vector of characters, which are typed as they are, and enclosed keycodes, which are pressed. A keycode is either the two-character code of an [action](../../windows-ui-guide/keyboard-shortcuts.md), such as `'ER'` (Enter), or a function key from `'F0'` to `'F255'`. Keycodes are case-sensitive.

Definitions belong to the session, and survive `)CLEAR` and `)LOAD`. They are held in a buffer whose size is set by the [`PFKEY_SIZE`](../../windows-installation-and-configuration-guide/configuration-parameters/pfkey-size.md) configuration parameter.
